# 技能创建决策 Rubric

使用该 rubric 决定是创建新的技能文件还是扩展现有的技能。

## 目的
- 保持路由清晰、可维护。
- 避免触发词重叠的重复技能。
- 仅当存在可重复、独立的工作流时才创建新技能。

## 决策标准
对每一项评分：
- `0` = 否
- `1` = 部分
- `2` = 是

1. 触发词缺口：新的用户措辞未被 [index.md](../index.md) 中现有的触发词映射条目覆盖。
2. 工作流缺口：执行步骤与现有技能有实质差异。
3. 产出缺口：交付物类型不同（例如：架构评审、分流备忘、事件邮件、解除阻塞流程）。
4. 工具或证据缺口：需要不同的工具、数据源或验证证据。
5. 复用可能性：该场景很可能在未来请求中再次出现。
6. 领域契合度：它在某个领域/子文件夹中有清晰的位置，并能改进路由清晰度。

## 评分指南
- `0-4`：不创建新技能。复用现有技能并优化其触发词/正文。
- `5-8`：临界。先扩展现有技能；确认会重复出现时才新建。
- `9-12`：创建新技能。

## 打破平局的规则
评分处于临界时应用：
1. 如果完全没有触发词匹配，优先补充触发词覆盖。
2. 如果交付物 + 工作流都独立，优先创建新技能。
3. 如果只是措辞不同，不要创建新技能。

## 最小工作流
1. 检查 [index.md](../index.md) 中的触发词映射。
2. 运行 rubric 并记录简短理由。
3. 如果是扩展现有技能：
- 更新技能 frontmatter 中的触发短语。
- 更新 [index.md](../index.md) 中的技能表和触发词映射。
4. 如果是创建新技能：
- 复制 [Working/_TEMPLATE.md](_TEMPLATE.md)（Living 领域用 `Living/_TEMPLATE.md`）。
- 填写 frontmatter，尤其是 `id` 和 `triggers`。
- 保存到正确的子文件夹。
- 在 [index.md](../index.md) 中加一行技能表条目和触发词映射条目。
5. **强制记忆同步**：本仓库内任何变更（新建 / 扩展 / 修改 / 移动 / 删除 / 重构 / 规则更新）之后，在当天向 `Memory/YYYY-MM-DD.md` 追加一条记录（必要时创建该文件）。参见 `README.md` → 记忆约定。
