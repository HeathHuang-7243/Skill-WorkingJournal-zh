# 云安全与合规

> 正文使用"控制映射 + 清单"版式。**我的角色**一节约定你如何嵌入安全团队工作流——这是你的个人参与模型，不是通用框架。把示例线程换成你实际的分工。

## 我在安全循环中的角色（三条线程 —— 示例）

| 线程 | 我做什么 | 交接 / 对应方 | 触发 |
|--------|----------|------------------------|---------|
| **漏洞分诊枢纽** | 拉取态势工具 + 门户 → 按家族列出有风险的资源 → 每个资源写一行摘要 → 分派。 | 分派 → **运维团队**执行；安全团队成员处理自己的分工。 | 每周（或每次态势刷新后）。 |
| **下放范围界定** | 与团队坐下来，列出哪些管理级任务可以移交给运维。产出：一份干净的可下放清单，供基础设施负责人带进领导层会议。 | 共同设计 → 安全；落地 → 基础设施负责人。 | 出现可下放候选时。 |
| **豁免提议** | 带理由（范围、接受的风险、缓解措施）提出关键豁免。提交签字。上线后跟踪安全分差变化。 | 提交 → **安全负责人**；分数影响在态势工具中可见。 | 业务对基线会强制要求的某项控制有异议时。 |

> 三条线程共享一条规则：**把所有权连同工作一起交接。** 半交接会产生来回乒乓球（见 `work-triage` ③）——如果可以下放，在量转移**之前**就决定你这边谁负责。

## 基线控制（映射到任何框架）
| 控制域 | 我实现什么 | 映射到 |
|-------------|------------------|-----------|
| 身份 | Entra ID / IAM、MFA、最小权限角色 | ISO A.9 / SOC CC |
| 网络 | NSG、私有端点、分段 | ISO A.13 |
| 数据 | 静态 + 传输中加密、密钥保管库 | ISO A.10 |
| 态势 | Defender / Config、持续评估 | SOC CC |
| 治理 | Azure Policy / Config 护栏 | ISO A.18 |
| 漏洞分诊 | 态势扫描 → 汇总有风险资源 → 分派给运维 | ISO A.12 / A.18 |
| 下放 / 供应商 | 共同设计哪些管理任务可以移到运维 | ISO A.15（供应商关系） |
| 豁免 / 风险处置 | 带理由提出关键豁免；提交安全负责人签字 | ISO A.6（风险处置） |

## 任务（合规就绪清单）

### 我负责的（我在安全循环中的分工）
- [ ] **漏洞扫描 + 分派** —— 态势工具 / 门户 → 按资源的摘要 → 用一行动作诉求邮件运维；抄送每项的安全负责人。
- [ ] **下放范围界定** —— 与安全坐下来，为基础设施负责人产出可下放的管理任务清单。
- [ ] **豁免提议** —— 提出关键豁免 + 建议（范围、接受的风险、缓解措施）→ 提交安全负责人签字；批准后观察安全分提升。
- [ ] **路由检查** —— 分派前，通过 `team-routing` 确认负责人（哪个安全人员拥有该分工）。

### 基线（人人有责）
- [ ] 身份基线：MFA 已强制、无常驻管理员、break-glass 账号已记录
- [ ] 网络基线：除有理由 + 已评审外，无公网暴露
- [ ] 数据基线：加密已验证、机密在保险库中（绝不在 IaC 里）
- [ ] 态势：策略 / Config 规则已部署；违规已路由给负责人
- [ ] 证据：控制 → 框架映射已为审计员记录
- [ ] 评审节奏：季度态势评审；每次重大变更后评审

## 证据 / 示例
- **实战漏洞分诊：** 每周态势拉取，给运维的摘要邮件；同时覆盖通用漏洞修复和容器漏洞两条线。
- **下放：** 共同构建了负责人带进领导层会议的可下放管理任务清单。
- **豁免：** 编制了带安全理由说明的优先豁免清单；安全负责人签字；安全分在下一份报告中可见提升。
- **产出：** 控制 → 框架对照表（链接放在这里）。

## 踩坑
- 合规是证据 + 控制，不是墙上的一张证书。记录映射关系。
- 没人拥有的控制会漂移；给每个控制指定负责人。
- 内建到 IaC 的安全（见 `infrastructure-as-code`）胜过事后补挂的安全。
- **漏洞分诊是前门。** 安全与运维只有在分派清单及时的情况下才能行动。跳过一周会悄悄拖慢整条链——把扫描当作按周期重复的承诺，不是一次性动作。
- **下放范围同时改变双方。** 工作移交运维时，内部团队必须放弃所有权——半交接会制造来回乒乓球（见 `work-triage` ③）。在量转移**之前**决定所有权。
- **豁免需要故事，不是一个勾选框。** 安全负责人签的是"风险接受的理由 + 缓解计划"，不是空请求。带上"为什么"，否则不要提。
- **路由提醒。** 分派前，通过 `team-routing` 确认哪个安全人员拥有该分工。
