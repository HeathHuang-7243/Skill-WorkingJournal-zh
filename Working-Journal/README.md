# Working-Journal

长期记忆仓库：工作在哪里发生、被记录、被归档。

## 目的
- **`daily/`** —— 逐日记录被请求了什么、产出了什么、下一步做什么。AI 助手每天早上读取它以恢复上下文并呈现未完结主题。
- **`active/`** —— 进行中的工作，按主题组织（每个事件 / 项目 / 项目一个文件夹）。
- **`Archive/`** —— 已关闭的工作，按项目归档。项目结束时把文件夹移到这里；保留供参考。

## 规则
1. **每日日志：** 为本工作区执行的任何操作，当天记入 `daily/<YYYY-MM-DD>.md`。
2. **最少内容：** 被请求了什么 · 产出/变更了什么 · 关键下一步或待定决策。
3. **路径：** 如果创建了产出文件，在日志中记录其相对路径。
4. **开工回看：** 每天第一次对话时，读取最近 7 天的 `daily/`，主动提出未完结主题（待办动作、阻塞项、未决决策）。
5. **双仓库上下文：** 每个工作日同时读取 `Skills/Memory/` 的最新记录和 `daily/` —— 上下文来自两个仓库。
6. **日志触发：** 当用户说出"记下来"、"做个笔记"、"写进日志"时，追加到当前日期的 `daily/<YYYY-MM-DD>.md`。

## 生命周期
```
传入的事件 / 任务
        ↓
active/<主题>/    ← 工作文件 + 草稿
        ↓  （完成）
daily/<日期>.md    ← 含路径的日志条目
        ↓  （项目关闭）
Archive/<项目>/ ← 参考副本
```

## 目录结构示例
```
Working-Journal/
├── README.md
├── daily/
│   ├── 2026-08-06.md
│   └── 2026-08-07.md
├── active/
│   ├── <主题A>/
│   └── <主题B>/
└── Archive/
    └── <项目-2026>/
